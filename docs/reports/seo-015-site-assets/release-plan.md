# SEO-015 全站资源检查与抓取入口修复

用户授权：检查所有页面、防止缺失资源复发并进一步提升访问量；沿用本任务已明确给出的修复、部署及持续跟进授权。

## 交付范围

- `scripts/audit-public-assets.py`：站点地图、发布HTML清单、站内页面与资源引用图的只读检查。文本资源GET；图片/字体等HEAD。检查状态、错误HTML和CSS/JS类型。外部第三方资源与任意脚本表达式不属于静态解析的完整覆盖，须辅以浏览器检查。
- `scripts/check-release-assets.py`：发布依赖门禁；资源必须在本次传输清单中或已在线可用，检查CSS嵌套依赖及静态可解析的动态加载路径。
- `scripts/lib/release-manager.mjs`：在前台发布目标中强制门禁；新增限定发布目标 `seo-assets`。
- `server/lib/catalog-list-prerender.js`：五个目录输出真实公开库存快捷链接，不依赖脚本生成，不修改原筛选、询价或数据结构。每类最多24个未售出条目。
- `docs/previews/seo-015-site-assets/`：卡车、发动机目录的无脚本功能预览；390px及桌面验证。预览禁索引、不部署。
- `docs/reports/seo-015-site-assets/`：全站审计、发布记录和监测基线。

## 发布

通过干净隔离分支提交、推送，再使用 Release Manager。仅传输明确清单内的生产文件。检查原文件哈希、备份及快照，安装失败自动回滚。重启后等待本机HTTP就绪，再执行公网验证，避免将systemd active误当HTTP已就绪。

## 验证与跟进

资源门禁5项针对性测试；目录链接4项测试（分类、售出排除、转义、数量上限和幂等）；安装脚本与相关发布检查。线上验证五个目录的链接及其资源图。原有心跳 `asiapower` 已更新：每6小时主要页面资源检查，每周一次全站检查，无变化安静，问题明确时按授权修复。

修复可抓取性不代表搜索流量已提高。继续比较完整7天/28天的GA4会话、GSC点击/展示与有效询盘。技术依据：[Google JavaScript SEO 文档](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)指出服务器输出内容和可抓取链接有助于用户与搜索爬虫发现内容。

## 全量审计后追加修复（同一用户授权范围）

全站共检查1,556个页面地址及5,692个资源地址；发现38条失败记录，其中CSS内SVG编码片段与Cloudflare邮箱保护链接2条为检查器边界，实际需修复36条。包括20个不存在的品牌页入口、10个已下架QXB商品链接、3个指南断链、3个临时图片地址。

- 详情页服务端和浏览器端统一链接到现有品牌库存筛选，避免依赖不存在的品牌HTML文件；相关发动机/变速箱入口同样改到现有目录。
- 8个发动机页的退休库存链接改成当前搜索，3个指南链接修正；生成器排除退休QXB来源，避免再次生成失效详情链接。
- 4个详情模板更新共享详情脚本版本。该脚本响应设置一年不可变缓存，不能只覆盖同名文件。
- 生产已有而分支缺失的两个指南已取回作为修改基线；其他涉及文件同样逐项比对生产哈希，不使用仓库旧版覆盖线上行为。
- HC250571的3张原图及3张缩略图均在R2原始存储核实存在。通过现有媒体晋升模块复制已审核商品的这6个文件，逐一验证公开访问，仅更新该商品照片URL。其他字段、其他记录及原始云对象保留。发布数据备份及该记录的旧照片字段保存在服务器发布目录。

生产发布清单为18个文件；修复媒体脚本作为一次性维护步骤在Release Manager备份后执行，不部署到公开站点。照片恢复属于数据修复，常规代码回滚不会重新换回已过期照片URL；如确需恢复旧字段，使用发布目录media-HC250571-before.json针对单记录操作，不可覆盖整库。
