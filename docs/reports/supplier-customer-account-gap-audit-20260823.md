# AsiaPower 供应商 / 客户账户与库存编辑差距审计

**日期**：2026-08-23
**状态**：本文件记录生产实现前的审计快照；对应实现边界与验证结果见 `supplier-inventory-management-production-20260823.md`。
**配套预览**：`docs/previews/supplier-media-management-v1/`

## 1. 结论先行

当前供应商后台不是“完全不能编辑”，而是**只完成了文本参数编辑的第一层**：供应商登录后能修改自己名下库存的品牌、型号、年份、价格、发动机号、变速箱号、驱动、里程、状态、短描述和备注。

它还没有完成我们已经确认的完整库存维护能力：

1. 不能新增、删除、替换、排序照片，也不能设置封面。
2. 不能上传、替换或移除视频。
3. 已上线商品的关键字段目前会直接覆盖公开库存，没有“新版本待审、旧版本继续在线”。
4. 没有私有证据归档、版本差异、操作者和前后值审计。
5. 没有安全下架、撤回审核、按拒绝原因修改后重新提交的完整流程。

因此本问题需要修复，而且不能只在页面上补几个按钮；它需要前端、接口、版本数据、媒体存储、审核和审计一起修改。

## 2. 事实、判断与假设的区分

### 2.1 已通过真实页面或当前代码验证的事实

- 生产 `https://asia-power.com/supplier-portal/dashboard.html` 返回 HTTP 200。
- 生产 `/api/half-cuts/my-uploads` 未登录返回 HTTP 401。
- 生产 `js/supplier-dashboard.js` 与本地文件 SHA-256 一致：`c961b7d3dac5729b0c919aa8f136e66d71f7dcde4006a1de15c304388edc3eb4`。
- 当前公开接口返回 599 条 approved 库存；预览选用真实库存 `HC250642`。
- `server/lib/half-cut-api.js` 会按 `supplierId` 或规范化手机号验证库存归属；管理员可管理全部库存。
- `SUPPLIER_EDITABLE_FIELDS` 只包含文本参数和库存状态，不包含 `photos`、`video`、`VIN`、封面顺序或下架字段。
- 已审核库存的供应商编辑会直接复用 `updateApprovedInventory()`；没有先创建 revision 的步骤。
- 当前供应商列表摘要只返回首张照片，不返回完整媒体清单。
- `server/lib/buyer-orders.js` 在创建订单时复制 `exwUsd`、定金比例和定金金额；现有订单不会因为以后库存价格变化自动重算。这符合“新价格只影响未来询价/订单”的原则。
- 供应商不能通过当前字段集合修改“已验证”标记；这一保护已经成立。
- 供应商上传仍允许通过旧的 upload key / upload token 流程，不强制必须是已登录供应商账户；登录绑定和旧公开上传路径仍然并存。
- 登录页仍把 Google 显示为买家主要入口；短信 OTP 界面被隐藏。
- `/api/auth/phone/password/set` 默认在 `AUTH_REQUIRE_SMS_OTP` 未启用时允许仅凭匹配手机号设置或修改密码；这不符合我们确认的账户找回安全规则。
- 买家中心目前只显示报价/定金订单表，没有完整的询价、报价确认、合同、付款凭证、备货、单据、物流和消息中心。
- 当前买家中心和供应商中心有固定英文/中文及 `v4` 技术字样，未形成中文、英文、法文、阿拉伯文统一门户。

### 2.2 设计判断

- “参数编辑 + 媒体编辑”应在同一个库存工作台中完成，避免供应商在多个旧上传页之间跳转。
- 价格和可售状态属于运营字段，可以即时生效，但必须写审计日志；其他影响商品身份或证据可信度的字段必须创建待审版本。
- 从公开商品移除媒体不应物理删除，因为原图是供应商提交和平台审核的证据。
- 国内供应商后台不能依赖 WhatsApp；站内通知、短信、邮箱和人工运营通道需要独立存在。
- 后台视觉应延续现有 AsiaPower 的克制、黑金、米灰和真实证据语言，而不是传统蓝色 SaaS 面板。

### 2.3 仍需在生产实施前确认的假设

- 私有证据归档的法务保留期，建议默认 24 个月；目前没有最终业务决定。
- 单条库存照片上限沿用 15 张，视频上限沿用现有上传配置；正式实现前需读取生产环境实际限制并保持一致。
- “已预订”是否允许供应商即时设置，还是只能由订单锁库触发；当前建议供应商可设置，但要有审计和冲突保护。
- 平台审核 SLA、谁可以批准 revision、拒绝原因枚举尚未最终确定。

## 4. 这次预览如何修复“编辑已上传内容”

交互预览包含：

- 读取真实公开库存，不使用虚假商品。
- 有视频时优先展示视频封面；首张照片作为静态后备封面。
- 新增照片、移除照片、恢复归档、前移/后移、拖动排序、设为备用封面。
- 上传或替换视频、移除视频。
- 私有证据归档区，明确展示“公开移除不等于物理删除”。
- 品牌自动大写、型号、年份、里程、价格与状态编辑。
- 目录卡片、移动端和详情页三种客户侧预览。
- 明确区分“即时生效字段”和“创建待审版本字段”。
- 所有保存/提交在预览中被拦截，不写生产数据。

## 5. 生产实现边界（全栈，不是只改几个页面）

### P0：权限、版本与账户安全

**预计涉及文件/组件**

- `server/lib/half-cut-api.js`：拆分即时字段与待审字段；所有写入先校验 ownership。
- 新建 `server/lib/inventory-revisions.js`：revision 创建、差异、审核、发布与冲突检查。
- 新建 `server/lib/inventory-audit-log.js`：价格、状态、版本发布和下架审计。
- `server/lib/phone-password-auth.js`、`server/lib/phone-otp-auth.js`：关闭仅手机号改密；恢复验证码/管理员邀请/邮件验证安全路径。
- 上传授权层与 `supplier-portal/*.html`：强制供应商登录后上传并绑定 `supplierId`；受信批量导入另走后台权限。
- 数据迁移脚本：给现有 approved 记录补 `publishedVersion`，不改变公开 URL、stockId 或现有库存内容。

**可复用现有代码**

- `supplierOwnsRecord()`、`findOwnedRecord()` 的归属判断。
- 现有 pending/approved/rejected 审核数据和管理员审核页。
- `json-store` 原子写入、现有上传 token/R2 封装和订单价格快照。

**影响页面**

- 全部供应商上传页、供应商工作台、管理员审核、登录/注册/找回。
- 公开目录与详情只读取 published 版本，外观与 URL 不应改变。

**风险与回退**

- 风险：历史库存缺少稳定 supplierId；需先生成“未绑定清单”，禁止自动误绑定。
- 风险：revision 发布时与运营人员同时改价；需字段级冲突检测。
- 回退：上线前备份 approved/submissions/users；功能开关回退到只读工作台；published 数据保持原格式兼容。

**验收标准**

- 未登录上传/编辑全部 401；A 供应商无法读取或编辑 B 供应商库存。
- 仅手机号不能重置任何现有账户密码。
- 关键字段编辑后公开 API/页面保持旧值，审核批准后原子切换新值。
- 即时价格/状态修改有 actor、时间、旧值、新值和原因。
- 既有 URL、stockId、SEO、询价和订单价格快照测试全部通过。

### P1：媒体工作台与完整库存生命周期

**预计涉及文件/组件**

- `supplier-portal/dashboard.html`、`js/supplier-dashboard.js`、`css/portal-app.css`：用已确认预览替换旧编辑表单。
- 新建 `js/supplier-media-editor.js`：上传、排序、封面、恢复、三种预览。
- `server/lib/half-cut-api.js`：媒体 revision、排序、封面、视频和安全下架 API。
- 新建 `server/lib/media-evidence-archive.js`：原始媒体证据、访问权限和恢复。
- 管理员审核页面：并排显示旧版本/新版本和媒体差异。
- 测试：ownership、并发、媒体限制、归档权限、移动端交互、公开版本不变。

**可复用现有代码**

- 现有 R2 预签名上传、媒体类型/大小校验、缩略图 URL、审核发布逻辑。
- 现有目录卡片和详情页渲染器作为预览组件的数据契约。

**影响页面**

- 供应商后台全部库存分类：半切车、发动机、变速箱、卡车、工程机械、二手车。
- 管理员审核页；公开目录和详情只在 revision 获批后更新。

**风险与回退**

- 风险：原始图片尺寸不一导致封面预览与公开页不同；必须复用公开页 `object-fit` 和视频优先规则。
- 风险：媒体归档成本增长；需保留期和生命周期策略，但不能无审计删除。
- 回退：媒体编辑功能开关关闭；已创建 revision 保留但不发布；公开版本不受影响。

**验收标准**

- 所有商品分类均可新增/移除/排序/设封面并管理视频，不是只支持二手车。
- 删除公开照片后，供应商普通接口不能再取公开 URL；管理员证据接口仍能看到原图与历史。
- 15 张照片、视频大小/类型、断点失败、重复提交和多标签页冲突都有明确错误。
- 360px、768px、1440px 三档可完整完成编辑和提交。

### P2：客户采购中心、RFQ 与全语言统一

**预计涉及文件/组件**

- `buyer-portal/index.html`、`js/buyer-portal.js`：询价、报价确认、合同/付款、备货、单据、物流时间线。
- 供应商中心新增 RFQ 机会与报价模块；新建 RFQ/offer 数据存储和 API。
- 登录与两个门户接入统一 i18n；中文、英文、法文、阿拉伯文及 RTL 验收。
- 国内通知接入短信/邮件/企业微信或站内消息，WhatsApp 仅作为海外快速通道。

**验收标准**

- 客户在一个账户内可追踪从询价到物流的完整状态，不引入传统购物车。
- 供应商只看到匿名化采购需求，不泄露买家手机号、邮箱、WhatsApp 或外部付款信息。
- 中文状态不夹杂 `Pending / Live / Add to quote list` 等英文；四语状态语义一一对应。
- RFQ 报价有供应商权限、截止时间、货币、交期、审计和人工确认边界。

## 6. 其他此前讨论过但仍未完成的产品事项

这些不应与本轮媒体修复混在一个发布中，但不能遗忘：

1. **供应商网络 + RFQ 广播多方比价**：既有需求文档将其列为战略优先级最高的新功能，真实站仍未实现。
2. **市场与合规中心及详情页合规提示**：已有内容基础，真实页面挂载点未建。
3. **买家证言与发货实证**：没有实现；必须等真实授权素材，不能生成虚假评价或信任数据。
4. **买家画像三入口 Track A/B/C**：旧方案设计过，但此后首页方向已经调整为循环经济与产品路由；是否继续实施应重新确认，不能当成当前必做项。
5. **订阅制批发价**：商业规则仍未决定，不是工程遗漏；需要先定价格、权限和权益。
6. **伙伴账户的账期、关注型号和等级标签**：需求提出过，尚未建立数据结构；是否保留需结合真实业务规则。

## 7. 推荐的发布拆分

不要把账户安全、媒体编辑、买家中心和 RFQ 一次性塞进同一生产发布。推荐：

1. Release A：账户找回安全、供应商强制登录绑定、revision/audit 基础。
2. Release B：媒体工作台、证据归档、审核差异、全分类支持。
3. Release C：供应商工作台信息架构、拒绝/撤回/重提、移动端和四语。
4. Release D：买家采购中心和 RFQ 双向撮合。

每个 Release 都必须通过 Release Manager，具备数据备份、功能开关、回滚脚本和公开页面回归验证。
